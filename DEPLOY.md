# Как выложить сайт на хостинг

Есть два варианта:

- **Статический экспорт** (папка `out/`) — заливка на PHP или статический хостинг без Node.js. Контент из WordPress подтягивается только в момент сборки; чтобы обновить сайт после правок в админке, нужен новый билд и повторная заливка.
- **SSR (Node)** — без `output: "export"` в конфиге, деплой на хостинг с Node.js. Страницы рендерятся на сервере. Публичные запросы к WordPress кешируются в Next Data Cache (~300 с, см. `wp-cms.config.mjs`). Правки в админке появляются в пределах этого TTL, не на каждый хит. Чтобы видеть CMS сразу — `WP_TEMP_FULL_DATA_CACHE = false`.

---

## Деплой в SSR-режиме (Node)

Если в `next.config.mjs` **нет** `output: "export"`, приложение собирается под Node и работает в режиме SSR.

1. **Сборка:** `npm run build` (папка `out/` не создаётся — результат в `.next`).
2. **Переменные окружения** на хостинге: `NEXT_PUBLIC_WP_API_URL` и при необходимости другие из `.env.local`.
3. **Запуск:** `npm run start` (или через PM2/systemd на VPS). Платформы вроде Vercel делают build и start сами при деплое из Git.

Детали по шагам — в разделах [Vercel](#vercel-если-нужен-node-хостинг) и [Свой сервер (VPS) с Node.js](#свой-сервер-vps-с-nodejs) ниже.

## Где держать WordPress (один домен, без второго)

Дополнительный домен не нужен. Всё на одном: **сайт в корне, WordPress в подпапке**.

1. **Корень домена** (public_html / www) — сюда заливаешь **содержимое папки `out/`**: главная, страницы, `_next/`, `images/` и т.д. Это то, что видят посетители.
2. **Подпапка для WordPress** — создай папку, например **`wp`** или **`admin`**, и установи туда WordPress (загрузка с wordpress.org → распаковка в эту папку, настройка через браузер: `https://твой-сайт.com/wp/` или `https://твой-сайт.com/admin/`).
3. В установленный WordPress поставь плагин **nextwp**: скопируй папку `nextwp` из проекта в `wp-content/plugins/nextwp`, в админке включи плагин.
4. В Next при сборке в `.env.local` укажи:
   ```env
   NEXT_PUBLIC_WP_API_URL=https://твой-сайт.com/wp
   ```
   (без слэша в конце; если папка `admin` — тогда `https://твой-сайт.com/admin`).

Итог: один домен, админка и API по адресу `твой-сайт.com/wp/` (или `/admin/`), фронт — в корне. В тему WordPress ничего закидывать не нужно — nextwp это плагин.

## PHP / обычный хостинг (статика из папки `out/`)

1. **Сборка** (нужен Node 20 и доступ к WordPress API на момент сборки):
   ```bash
   nvm use 20
   npm run build
   ```
   В корне проекта появится папка **`out/`** — в ней готовый сайт: папки с `index.html`, JS, CSS, картинки.

2. **Переменные при сборке** (в `.env.local` или в окружении):
   - `NEXT_PUBLIC_WP_API_URL` — URL сайта WordPress (например `https://rapha.tim-work.com`), чтобы подтянуть страницы/новости/услуги при сборке.
   - По желанию: `NEXT_PUBLIC_SITE_URL` — полный URL будущего сайта (для ссылок «поделиться» в новостях, например `https://твой-домен.com`).

3. **Заливка на хостинг**: содержимое папки **`out/`** (все файлы и папки внутри) залей в корень сайта на хостинге (public_html, www, htdocs и т.п.). Сервер будет отдавать `index.html` из каждой папки.

4. **Если нужен редирект** (например со старого URL на новый), добавь в `.htaccess` в корне (внутри `out/` потом не трогай — заливай уже с нужным .htaccess в корне сайта на хостинге):
   ```apache
   Redirect 301 /services/surgery--operating-room /services/surgery-operating-room/
   ```

Контент (страницы, новости, услуги) подтягивается из WordPress **в момент сборки**. Чтобы обновить контент на сайте, заново сделай `npm run build` и снова залей папку `out/`.

**Важно:** не открывай `index.html` из папки `out/` двойным щелчком (протокол `file://`) — шрифты и скрипты не загрузятся (CORS и неправильные пути). Чтобы посмотреть экспорт локально, запусти: `npm run preview` и открой в браузере **http://localhost:3000**.

## Другие варианты

### Vercel (если нужен Node-хостинг)

Vercel — хостинг от создателей Next.js, бесплатный тариф есть.

1. Залей проект в **GitHub** (или GitLab/Bitbucket).
2. Зайди на [vercel.com](https://vercel.com), войди через GitHub.
3. **Add New Project** → выбери репозиторий `rapha`.
4. Оставь настройки по умолчанию (Framework: Next.js, Build Command: `npm run build`, Output: оставь как есть).
5. В **Environment Variables** добавь переменные из твоего `.env.local`:
   - `NEXT_PUBLIC_WP_API_URL` (и другие, если есть)
   — чтобы на проде работала связка с WordPress.
6. Нажми **Deploy**. Через пару минут будет ссылка вида `https://твой-проект.vercel.app`.

Дальше при каждом пуше в ветку (например `main`) Vercel сам сделает `npm run build` и обновит сайт.

### Свой сервер (VPS) с Node.js

Если хостинг — твой сервер (VPS, VDS и т.п.) с установленным **Node.js 20+**:

1. Залей на сервер код (git clone или через FTP/SFTP).
2. На сервере в папке проекта:
   ```bash
   npm install
   npm run build
   ```
3. Создай файл с переменными окружения (как `.env.local`, но на сервере) или экспортируй их в shell.
4. Запусти приложение:
   - один раз вручную: `npm run start` (порт по умолчанию 3000);
   - или через **PM2**, чтобы работало в фоне и после перезагрузки:
     ```bash
     npm install -g pm2
     pm2 start npm --name "rapha" -- start
     pm2 save && pm2 startup
     ```
5. Настрой **Nginx** (или другой веб‑сервер) как reverse proxy на порт 3000 и привяжи домен (SSL через Let's Encrypt и т.п.).

На таком хостинге «итоговые» файлы — это весь проект: исходники + `node_modules` + папка `.next` после `npm run build`. Отдельной папки с .html нет: сайт отдаётся через `npm run start`.

---

## Важно про переменные

Переменные из `.env.local` (особенно `NEXT_PUBLIC_WP_API_URL` для WordPress API) на хостинге нужно задать там же, где запускаешь приложение: в настройках Vercel (Environment Variables) или в окружении на своём сервере. Иначе прод не будет знать, откуда тянуть контент.
